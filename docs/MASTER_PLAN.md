# Genesis Garden — план реализации закрытой беты

Источник требований: мастер-промт David (полный текст сохранён в проекте Claude «GENESIS GARDEN»). Порядок этапов соответствует мастер-промту 1:1, без пропусков. Статус каждого этапа — в `docs/IMPLEMENTATION_STATUS.md`, обновляется по ходу работы, это единственный источник правды о прогрессе.

1. **Аудит и стабилизация** — `docs/AUDIT.md`. Готово.
2. **Чистая игровая модель** — единый конфиг баланса (`src/game/config.ts`), сквозной seeded RNG, Vitest + unit-тесты генетики/экономики/pity/миграции/идемпотентности.
3. **Supabase** — SQL-миграции, RLS, RPC для всех изменяющих операций, seed-данные, `.env.example`, TS-типы из схемы.
4. **Аккаунты** — гость → Supabase Auth (magic link как рабочий вариант; OAuth задокументирован как расширение), перенос localStorage → облако, офлайн-очередь.
5. **Reveal-loop и генетика** — путь до первого скрещивания ≤10 мин, полная reveal-последовательность, пыль/фиксация признака, доступность (44×44 px, reduced-motion, звук/вибро-тумблеры).
6. **Социальный обмен** — подарки по публичному коду, лимиты, история, блокировка, без рынка и чата.
7. **Монетизация** — `PaymentProvider` интерфейс, mock + Paddle sandbox adapter, webhook с идемпотентностью, entitlements, feature flag на production.
8. **Аналитика и админка** — типизированные события → Supabase, защищённая ролью админ-страница с воронкой.
9. **PWA/UX/производительность** — manifest, offline, code-splitting Phaser-чанка (см. AUDIT.md), безопасные зоны, картинки.
10. **Тесты** — unit/integration/RLS/E2E критических сценариев (5 сценариев из мастер-промта).
11. **CI/CD** — GitHub Actions: install→lint→typecheck→test→build→deploy(Pages), smoke test после деплоя.
12. **Документация** — README/CLAUDE.md/docs/*, `BETA_RUNBOOK.md`, финальный отчёт.

## Технические решения, зафиксированные на старте
- Backend: Supabase (Postgres + Auth + Edge Functions/RPC), т.к. это единственный вариант в мастер-промте и не требует своего сервера — совместимо с GitHub Pages как чисто статическим фронтендом.
- Таймеры — ленивые, по `planted_at`/`ready_at`, без крон-процессов (уже так реализовано на клиенте, сервер унаследует тот же принцип).
- Оплата — `PaymentProvider` интерфейс с двумя реализациями (`mock`, `paddle-sandbox`); Paddle выбран по рекомендации мастер-промта для владельца из Грузии, но требует аккаунта — пока недоступен, работаем в mock-режиме, адаптер готовим полностью.
- Монорепо-структура `apps/web` сохраняется как есть; серверный код (Supabase migrations/functions) добавляется в `supabase/` в корне репозитория рядом с `apps/`.
