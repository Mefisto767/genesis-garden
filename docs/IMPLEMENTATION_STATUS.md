## Этап 4 — Аккаунты — построено и протестировано, ВЫКЛЮЧЕНО по умолчанию (feature flag)
Ключевое архитектурное решение этого этапа: весь облачный слой собран и
покрыт тестами, но активируется только через `VITE_CLOUD_SYNC_ENABLED=true` +
реальные `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` (см.
`apps/web/.env.example`). Пока флаг выключен (по умолчанию — нет реального
Supabase-проекта), игра работает БУКВАЛЬНО как раньше — `AuthGate` сразу
отдаёт `<App/>` без единого лишнего экрана. Причина: подключать основной
игровой цикл к серверным RPC без возможности живого end-to-end теста против
настоящего Supabase-проекта — риск сломать протестированный, рабочий путь
игрока ради непроверенной интеграции. Как только у владельца появится
Supabase-проект, включение — это только `.env` + ручная проверка, без
изменений кода.

- ✅ `auth/AuthContext.tsx` + `auth/useAuth.ts` — сессия, `signInAsGuest()` (Supabase anonymous auth), `signInWithEmail()` (magic link — рабочий fallback без внешней настройки OAuth, как требует мастер-промт), `signOut()`, восстановление сессии (встроено в supabase-js), состояния loading/error.
