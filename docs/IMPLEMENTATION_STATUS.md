## Этап 2 — Чистая игровая модель — готово
- ✅ Единый конфиг баланса `src/game/config.ts` — все числа экономики, генетики, редкости, бустов и квестов в одном месте. `genetics.ts`, `store.ts`, `seedCatalog.ts` больше не хранят магические числа локально.
- ✅ Сквозной seeded RNG (`src/game/rng.ts`, mulberry32) — `GameStore` принимает `rng` в конструкторе, `breed()`/`randomGenome()` уже были параметризованы и теперь используются с общим rng экземпляра стора.
- ✅ Добавлены модули `entitlements.ts` (ускорители роста, лимит 25% суммарно — правило мастер-промта) и `quests.ts` (квесты onboarding: первая посадка/сбор/скрещивание + "5 сборов"), интегрированы в `GameStore` и `GameState` (миграция схемы v2→v3).
- ✅ **Важная находка и исправление**: `store.ts` (чистая модель) транзитивно тянул `import Phaser` через `seedCatalog.ts → plantArt.ts`, из-за чего Vitest падал при инициализации Phaser в jsdom. Разделено на `plantPalette.ts` (чистые данные: палитра/ключи текстур/URL, без Phaser) и `plantArt.ts` (только Phaser-рендеринг: `preloadSpecies`/`buildPlantSprite`). Теперь игровая модель по-настоящему независима от UI/рендер-слоя, как требует Этап 2.
- ✅ `GardenScene.ts` больше не дублирует расчёт `elapsed/ready/progress` — использует новый `gameStore.plotStatus(plot, now)`, единую точку правды, которую теперь использует и `harvest()`. Убран дубль логики.
- ✅ Vitest подключён (`vitest.config.ts`, environment jsdom), 34 unit-теста в `genetics.test.ts` и `store.test.ts`:
  - наследование каждого гена (без мутации — строго от родителя; с мутацией — из пула);
  - статистическая проверка таблицы вероятностей мутации (4000 испытаний, seeded rng, допуск ±5%);
  - pity-счётчик (рост, сброс, гарантированная мутация на пороге);
  - границы редкости (common/uncommon/rare/epic по очкам, legendary по именной мутации);
  - начисление/списание валюты (покупка, сбор, разблокировка, защита от отрицательного баланса);
  - применение и ограничение ускорителей роста (в т.ч. потолок 25%, истёкшие бусты);
  - офлайн-рост (расчёт по дельте `planted_at`, без фонового процесса — 2 часа "офлайн" корректно завершают рост);
  - миграция сохранения v2→v3 без потери прогресса (монеты/пыль/pity/инвентарь/специмены сохранены, новые поля — с дефолтами);
  - устойчивость к повреждённому JSON в сохранении (откат на новую игру, не крашится);
  - идемпотентность повторного запроса (двойной `harvest`/`claimQuest` не начисляет награду дважды; `breedSpecimens(id, id)` отклоняется).
- ✅ Проверка регрессии: `npm run lint`, `npm run build` (tsc+vite), оба существующих Playwright E2E-скрипта (`test-e2e.mjs`, `test-e2e-genetics.mjs`) — все зелёные после рефактора.

## Открытые вопросы владельцу (пока не блокируют работу)
1. **GitHub push-доступ**: у сессии нет PAT/`gh auth` для пуша в `Mefisto767/genesis-garden`. Работа продолжается локальными коммитами в песочнице; когда будет готов очередной стабильный этап, потребуется либо PAT (repo scope) от владельца, либо сам владелец должен будет запушить подготовленную ветку/патч.
2. **Supabase проект**: понадобится URL + anon key (публичные, можно передать в чат) для реальной интеграции; до этого момента вся работа Этапа 3 идёт как воспроизводимые миграции + локальный Supabase CLI (если будет установлен) — интеграция в живой проект произойдёт, когда ключи появятся.
